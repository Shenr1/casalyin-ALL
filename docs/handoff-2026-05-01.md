## 二、农艺师 slug 字段和 URL 格式修改

### 修改目的
- 添加 slug 字段，支持 SEO 友好的 URL
- 修改 URL 格式为 `slug + id`（参考产品 URL 格式）
- 修复农艺师详情页缺少服务城市和联系方式的问题

### 修改的文件

**后端**（7 个文件）：
- 数据库迁移：
  - `casalyin-java/casalyin-admin/src/main/resources/db/migration/V24__add_agronomist_slug.sql`
  - `casalyin-java/casalyin-admin/src/main/resources/db/migration/V25__update_agronomist_slug_from_name.sql`
- Entity：`AgronomistEntity.java`
- VO：`AgronomistPublicVO.java`、`AgronomistVO.java`、`AgronomistDetailVO.java`
- Service：`AgronomistService.java`、`AgronomistAuditService.java`

**前端**（8 个文件）：
- API 路由：`casalyin-Headless/app/api/agronomist/public/detail/id/[id]/route.ts`（新增）
- 页面：
  - `casalyin-Headless/app/cultivos/[slug]/page.tsx`
  - `casalyin-Headless/app/plagas/[slug]/page.tsx`
  - `casalyin-Headless/app/productos/[slug]/page.tsx`
  - `casalyin-Headless/app/agronomists/page.tsx`
  - `casalyin-Headless/app/agronomists/[slug]/page.tsx`
- 组件：`casalyin-Headless/components/CompactMultiDimensionResults.tsx`
- API：`casalyin-Headless/lib/agronomist-api.ts`

### 主要改动

#### 1. 数据库层
- **V24 迁移**：为 `t_agronomist` 表添加 `slug` 字段（varchar(200)），添加唯一索引
- **V25 迁移**：将现有记录的 slug 从 `agronomist-{id}` 更新为基于名称的 slug（如 `dr-sarah-martinez`）

#### 2. 后端代码
- **Entity 层**：`AgronomistEntity` 添加 `slug` 字段
- **VO 层**：`AgronomistPublicVO`、`AgronomistVO`、`AgronomistDetailVO` 添加 `slug` 字段
- **Service 层**：
  - 所有方法使用数据库 slug（不再动态生成）
  - 创建/更新农艺师时自动生成 slug（使用 `SlugUtil.toSlug()`）
  - `getPublishedBySlug` 和 `getPublishedById` 方法填充 `contacts` 和 `cities` 字段

#### 3. 前端代码
- **URL 格式**：所有生成农艺师链接的地方改为 `/agronomists/{slug}?id={id}`
- **路由处理**：农艺师详情页优先使用 `id` 参数查询，fallback 到 `slug` 查询
- **API 路由**：新增 Next.js API 路由代理到后端服务
- **详情页展示**：已有服务城市和联系方式的展示逻辑

### 预期效果
- **URL 格式**：`/agronomists/dr-sarah-martinez?id=6001`（SEO 友好 + 精确定位）
- **详情页展示**：显示服务城市（Badge 组件）和联系方式（弹窗）

## 五、可能的问题和解决方案

### 1. Flyway 迁移失败

**问题**：V24 或 V25 迁移执行失败

**解决方案**：
```bash
# 检查 Flyway 迁移历史
SELECT * FROM flyway_schema_history ORDER BY installed_rank DESC LIMIT 5;

# 如果 V24 失败，检查 slug 字段是否已存在
SHOW COLUMNS FROM t_agronomist LIKE 'slug';

# 如果 V25 失败，检查是否有 slug 冲突
SELECT slug, COUNT(*) FROM t_agronomist GROUP BY slug HAVING COUNT(*) > 1;
```

### 2. 前端 API 调用 404

**问题**：前端调用 `/api/agronomist/public/detail/id/6001` 返回 404

**解决方案**：
- 检查 Next.js API 路由文件是否存在：`app/api/agronomist/public/detail/id/[id]/route.ts`
- 检查后端服务是否正常运行（端口 8690）
- 检查 `getApiBaseUrl()` 函数是否返回正确的后端地址

### 3. 农艺师详情页不显示服务城市和联系方式

**问题**：详情页加载成功，但不显示服务城市和联系方式

**解决方案**：
- 检查后端 API 返回的数据是否包含 `contacts` 和 `cities` 字段
- 检查数据库中农艺师记录是否有这些字段的数据
- 如果数据库为空，在后台管理页面编辑农艺师，添加服务城市和联系方式

### 4. slug 格式不正确

**问题**：slug 仍然是 `agronomist-6001` 格式

**解决方案**：
- 检查 V25 迁移是否执行成功
- 手动执行 V25 迁移脚本
- 或者在后台管理页面编辑农艺师名称，触发 slug 自动更新
